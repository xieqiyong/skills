# Nullbyte Explainer Board

把技术概念、流程关系、状态变化和架构逻辑，整理成适合中文自媒体传播的“可爱技术图解板”。重点不是做学术论文图，而是把复杂机制讲到一眼能懂、愿意收藏、适合转发。

## Workflow

1. 先判断图解类型：
   - `工作原理图`: 解释一个核心机制怎么运作
   - `流程图`: 解释步骤、顺序、分支或回路
   - `对比图`: 解释有 / 无、前 / 后、旧 / 新的差异
   - `架构图`: 解释角色、模块、服务、调用关系
   - `状态变化图`: 解释输入、处理中间态、最终结果
2. 再决定画面结构：
   - `左-中-右原理板`: 左边输入，中间机制，右边结果或对比
   - `编号步骤板`: `1-2-3-4` 分段讲解
   - `前后对比板`: 两组状态并排 + 差异说明
   - `模块关系板`: 多个角色 / 服务围绕中心主题
3. 把内容压缩成 `3-6` 个核心模块：
   - 一个总标题
   - 一句副标题
   - `3-5` 个主说明块
   - 一个底部总结条
4. 保持文字短而可扫：
   - 标题尽量控制在 `8-18` 个汉字
   - 模块小标题尽量控制在 `4-10` 个汉字
   - 单个说明块尽量控制在 `1-3` 行短句
   - JSON、命令、状态字段只保留最关键部分
5. 用户要风格更接近参考图时：
   - 打开 `references/visual-system.md`
   - 打开 `references/layout-presets.md`
   - 打开 `references/usage-examples.md`
6. 用户要 `出图`、`做图`、`直接生成` 时，调用 `image_gen`。
7. 用户要 `文案`、`版式`、`提示词` 时，先返回结构化文本，不直接出图。

## Defaults

如果用户只给一个主题并直接说 `出图`，默认：

- 输出 `1` 张主图解板
- 比例默认 `3:2` 横版
- 结构默认 `标题 + 3 个编号分区 + 底部总结条`
- 右下角加轻量品牌签名：`@NullByte·零`

如果概念明显更复杂，或者用户说 `整套`、`多张图`、`分页`，默认扩成：

- `第1张`: 主原理图 / 总览图
- `第2张`: 细节拆解图 / 前后对比图
- `第3张`: 总结图 / 易错点 / 一句话记忆点

如果用户没说比例，优先用：

- `3:2` 横版：适合工作原理图、流程图、对比图
- `4:5` 竖版：适合多层模块图、发布型卡片

## Copy Rules

- 先讲结论，再讲机制。
- 模块标题要像手写笔记里的分区标题，不要像 PPT 小节。
- 优先用“谁在做什么，会产生什么结果”来解释，而不是堆术语。
- 比较类内容优先写成：
  - `无 X 会怎样`
  - `有 X 会怎样`
  - `差别是什么`
- 如果素材里有代码、JSON、状态字段，只截最能说明问题的最小片段。
- 底部总结条必须像“老师画重点”，一句话就能复述全图核心。

## Visual Rules

- 这套 skill 默认走 `白板笔记 + 可爱技术图解`，不是深色科技海报。
- 画面优先像“手绘讲解板”：白底、圆角框、彩色分区、手写感标题、箭头、星星、下划线、虚线框。
- 模块之间要有明显颜色分组，但不要满屏重色块。
- 同一张图里优先使用 `4-6` 种柔和强调色，不要单色到底。
- 允许放可爱机器人、小图标、表情符号式提示，只要它们服务于解释。
- 中心机制块要最醒目，左右输入输出块次之，底部总结最短但必须显眼。
- 参考图的阅读节奏可以接近，但不要逐像素照搬。

## Avoid

- 不要做成企业培训 PPT 风。
- 不要默认深色背景、霓虹灯、赛博朋克、玻璃拟态。
- 不要把一整段长文原封不动塞进图里。
- 不要让箭头、装饰和贴纸比信息更抢眼。
- 不要让每个模块都一样大；要有主次层级。
- 不要为了“可爱”牺牲逻辑清晰度。

## Output Modes

- 用户要 `文案`: 返回每个模块该写什么
- 用户要 `版式`: 返回结构草图和分区说明
- 用户要 `提示词`: 返回可以直接出图的 prompt
- 用户要 `出图`: 直接生成图片
- 用户要 `整套`: 返回 `主原理图 + 细节图 + 总结图`
