# 今日分享 AI 开源项目｜一键完整交付 Skill v2

把一个近期值得关注的开源 AI 项目，整理成适合公众号贴图、微头条、社交平台图文发布的一套完整内容。

默认栏目风格：`@NullByte·零`

默认目标不是只生成图片，而是一次性交付完整成品：

1. `1` 个经过核验的开源 AI 项目
2. `1` 个最推荐标题
3. `4-6` 个备选标题
4. `4` 张独立竖版图片
5. `1` 段公众号配图文案
6. `1` 段微头条短文案
7. `3-5` 个匹配项目方向的话题标签
8. `1` 条事实核验说明

固定四页结构：

1. 今日分享开源项目
2. 推荐理由
3. 解决了什么问题
4. 推荐指数几个星

## 一、触发词

当用户输入以下表达时启用：

- `今日分享项目，请帮我出图`
- `今日分享项目，先给我看`
- `继续做一期今日分享项目`
- `依据这个 skills，直接给我做一整套`
- `选题、出图、标题、文案一次性给我`
- `不要分步，直接完整输出`
- `最近有哪些值得关注的 AI Agent 开源项目`
- `帮我选一个最近比较火的 AI 项目做贴图`
- `做一个 GitHub 开源项目推荐卡片`

用户只输入：

```text
今日分享项目，请帮我出图
```

也必须自动完成：

```text
选题 → 信息核验 → 标题 → 四页文案 → 生成四张图 → 公众号文案 → 微头条文案 → 话题标签 → 完整交付
```

## 二、工作模式

### 模式 A：用户指定项目

用户给出 GitHub 链接、项目名、README、截图或上一轮已经确定的项目时，直接围绕该项目整理。

### 模式 B：自动选择项目

用户没有指定项目，只说“今日分享项目，请帮我出图”时，先通过最新公开信息筛选一个项目。

优先关注：

- AI Agent
- MCP
- Coding Agent
- Workflow Runtime
- RAG
- Agent Memory
- Agent Governance
- Voice Agent
- AI 工程工具
- 开发者生产力工具

### 模式 C：先看草稿

用户明确说以下表达时，只返回草稿，不生成图片：

- `先给我看`
- `先看文案`
- `先别出图`
- `我觉得可以，再让你生成图片`

返回内容：

1. 选中的项目
2. 选题理由
3. 主标题与备选标题
4. 四页贴图文案草稿
5. 公众号文案
6. 微头条文案
7. 话题标签
8. 等待用户确认

### 模式 D：一键完整交付

只要用户没有明确要求“先看草稿”，默认进入一键完整交付模式。

必须一次性完成：

1. 选题与信息核验
2. 生成标题
3. 生成四页贴图内容
4. 直接生成 `4` 张图片
5. 输出公众号文案
6. 输出微头条文案
7. 输出话题标签
8. 补充事实核验说明

## 三、自动选题规则

选题不是简单搬运 GitHub 热榜，而是做一次“信号筛选”。优先选择：

1. 近期仍有真实热度：Stars、Forks、Release、Commit、Issue 或 PR 活跃。
2. 解决明确问题：不是只有 Demo，能说明实际使用场景。
3. 适合做成 4 张图：定位清楚、推荐理由明确、痛点具体。
4. 信息来源可靠：优先 GitHub 官方仓库、README、Docs、Release。
5. 不只看 Star 数量：热度只是信号，真正重要的是值不值得现在花时间看。
6. 与开发者实际需求有关：能学习、能部署、能扩展、能做二次开发。

自动选择项目时，先筛选 `3-5` 个候选，只选 `1` 个最适合做图的项目。

## 四、事实核验规则

当用户要求“最近”“本周”“热度高”“GitHub 热榜”“最新”或默认自动选题时，必须联网搜索。

至少确认：

- GitHub 官方仓库地址
- 当前 Star 数量
- 当前 Fork 数量
- 最近更新时间
- 最近 Release 或 Commit 情况
- README 中明确写出的核心能力
- 项目定位是否与贴图内容一致

不得编造：

- Star 增长速度
- 排名
- 下载量
- 用户量
- 发布时间
- 版本号
- 官方功能
- 性能数据
- 生产可用性结论

无法确认的数据，不要写具体数字。

如果数据可能已经变化，正文中使用：

```text
截至本次核验，项目约有 <Stars> Stars、<Forks> Forks。
```

## 五、固定输出流程

### Step 1：确定项目

如果用户没有指定项目：

1. 搜索近期 AI 开源热点
2. 筛选 `3-5` 个候选
3. 只选 `1` 个最适合做图的项目
4. 简要说明为什么选它

### Step 2：完成事实核验

至少核验：

```text
仓库地址 / Stars / Forks / 最新更新 / Release 或 Commit / README 核心能力
```

### Step 3：生成标题

必须输出：

- `1` 个主标题：最适合公众号或微头条，优先使用
- `4-6` 个备选标题：覆盖不同风格

标题应包含以下至少一个要素：

- 明确痛点
- 项目亮点
- 数据信号
- 悬念
- 适合人群
- 值得关注的原因

避免：

- 过度标题党
- 无依据的夸张
- “无敌”“颠覆一切”“必须学”
- 为了吸引点击捏造数据

### Step 4：提炼四页内容

围绕四个问题整理：

1. 这是什么项目？
2. 为什么推荐？
3. 它解决了什么问题？
4. 值得给几颗星？

### Step 5：生成四张独立图片

除非用户明确要求“先看草稿”，否则直接生成 `4` 张独立竖版图片。

### Step 6：输出发布文案

必须同时输出：

1. `1` 段公众号配图文案：推荐 `100-180` 字
2. `1` 段微头条短文案：推荐 `60-120` 字
3. `3-5` 个话题标签

### Step 7：完整交付

最终回复按固定顺序返回，不能漏项。

## 六、标题生成规则

### 主标题

要求：

- 一眼能看出项目方向
- 有价值判断
- 尽量体现痛点或项目差异点
- 可以引用已核验的数据，但不要堆数字
- 控制在 `18-35` 个汉字左右

推荐标题结构：

```text
<痛点>？这个 <Stars> Star 的 <项目方向> 项目给出了另一种答案
```

```text
<项目名>：把 <能力1>、<能力2> 和 <能力3> 做成一个轻量运行时
```

```text
我发现一个很适合学习 <方向> 底层的开源项目：<项目名>
```

```text
不是 Demo，<项目名> 正在把 <方向> 做成真正可运行的底座
```

### 备选标题

至少覆盖以下 `3` 种风格：

1. 偏技术感
2. 偏吸引点击
3. 偏公众号栏目风格

## 八、推荐指数规则

推荐指数是编辑判断，不是客观评分。

- `★★★★★ 5.0 星`：已经成熟、现在就能用、价值明确、适合多数读者。
- `★★★★☆ 4.5 星`：值得立刻关注，功能完整，有真实场景，仍有少量门槛。
- `★★★★☆ 4.0 星`：值得收藏，趋势真实，对特定人群有价值，还需观察。
- `★★★☆☆ 3.5 星`：有意思，可以关注，但不建议立刻投入太多时间。

不要为了吸引眼球随意给 5 星。

要求：

- 推荐 `100-180` 字
- 包含项目名、项目方向、推荐理由、解决的问题、适合人群
- 语气专业但不生硬
- 能和四张图一起发布
- 不重复堆砌图片里的全部信息

默认模板：

```text
今日分享一个值得关注的 AI 开源项目：<项目名>。

真正有价值的地方，是 <项目的核心价值>。
适合 <目标人群> 收藏，尤其适合关注 <方向> 的开发者。
```

### 微头条短文案

要求：

- 推荐 `60-120` 字
- 开头尽快抛出项目名与核心判断
- 适合社交平台快速阅读
- 可以更直接，但不要夸张

默认模板：

```text
今天挖到一个值得收藏的开源项目：<项目名>。

想了解 <方向>，又不想一上来就被重框架劝退，可以先看看。
```

## 十三、文案语气

保持 `@NullByte·零` 栏目风格：

- 先说判断，再解释原因
- 专业，但不要写成论文
- 克制，不浮夸

- 多说“值不值得试”
- 少说“颠覆行业”

- `值得跟`
- `先收藏`

- `史诗级`
- `彻底颠覆`
- `无敌`
- `秒杀一切`
- `程序员必须学`

## 十六、核心原则

每一期都要让读者快速回答四个问题：

1. 这是什么项目？
2. 为什么值得推荐？
3. 它解决了什么问题？
4. 值不值得现在试？

同时，让发布者拿到内容后不需要二次补充：

```text
有图、有标题、有文案、有标签、有事实依据，复制即可发布。
```
