# 去AI味写作 Skill

## 为什么要去AI味

不是为了好看，是因为**平台会检测**。头条、公众号、百家号都有 AI 内容识别系统，被识别后直接限流。AI 内容的特征是统计层面的——句子长度分布太均匀、词汇多样性太低、结构太规则。去 AI 味的本质是打破这些统计特征。

---

## 平台检测的核心信号（必须规避）

### 1. 结构信号
- **段落等长**：每段都是 3-5 句，平台一眼就看出来。**必须**：有的段只有一句话，有的段 7-8 句
- **对称结构**：小标题下内容量几乎相同。**必须**：有的节写 200 字，有的节写 50 字
- **三段论**："首先...其次...最后..." 或 "第一...第二...第三..."。**禁止使用**

### 2. 词汇信号
- **高频套词**：以下词汇是 AI 检测的高权重信号，全部禁止：

| 绝对禁止 | 替代方式 |
|---------|---------|
| 值得注意的是 | 删掉，直接说 |
| 不可否认 | 删掉 |
| 在当今社会/时代 | 删掉，直接切入 |
| 综上所述/总而言之 | 不要总结，直接结束 |
| 具有重要意义 | 说清楚对谁重要、怎么重要 |
| 引发广泛关注/引发热议 | 说具体数字或反应 |
| 深刻影响/深远影响 | 说具体影响了什么 |
| 显著提升/大幅提高 | 给数字 |
| 进一步/进而 | 直接说下一件事 |
| 与此同时 | 删掉或用"但是" |
| 毫无疑问 | 删掉 |
| 不言而喻 | 删掉 |
| 应运而生 | 说清楚怎么来的 |
| 赋能/助力 | 说具体做了什么 |
| 令人唏嘘/引人深思 | 删掉，读者自己会想 |
| 一场...的变革 | 说具体变了什么 |
| 据XX报道/据XX消息 | 删掉来源，直接陈述事实 |
| 说白了/说人话就是/简单说/换句话说 | 删掉，直接写具体场景 |
| 本质上/归根结底 | 如果后面没有新判断，整句删掉 |
| 残忍/扎心/醒醒吧/最离谱/王炸/炸裂/别不信 | 禁用，改成克制判断 |
| 吃掉/碾压/暴击/吓坏/全网炸了 | 不用于标题和小标题 |
| 值得今天写/值得写它/这个选题/流量爆点 | 不要出现在正文，改成“读者为什么会在意”“它影响谁”“下一步该看什么” |

- **禁止标注信息来源**：不写"据36氪报道""XX媒体报道称""XX发布消息称""据XX旗下《XX》报道"。既然事实有迹可循，直接陈述事实本身，不需要告诉读者你从哪看到的。错误示例：~~"2026年5月13日，36氪旗下《智能涌现》发了一条独家报道：前阿里通义千问技术负责人林俊旸已经正式创业"~~ → 正确写法："5月13日，前阿里通义千问技术负责人林俊旸正式创业"

### 3. 句式信号
- **连续三句结构相同**：比如连续三句都是"X是Y，Z是W"。**必须**：相邻两句的句式不能一样
- **每句都很完整**：AI 写的每句话都是完整的主谓宾。**必须**：偶尔用短句、省略句、口语化断句
- **排比句**："有的人...有的人...有的人..."。**禁止**
- **感叹号堆砌**：连续感叹号。**禁止**

### 4. 语气信号
- **假装客观**："当然，我们也要看到另一面..."。**禁止**——要有立场
- **万能过渡**："接下来我们来看..." / "让我们把目光转向..."。**全部删掉**
- **强行升华**：写个具体事非要上升到"时代""人性""社会意义"。**禁止**
- **和稀泥**："有利有弊""需要辩证看待""凡事都有两面性"。**禁止**——要么支持要么反对
- **短视频口播腔**："说白了""醒醒吧""这才是最残忍的""真正的真相来了"。**禁止**——这些词会直接暴露 AI 模板感

### 5. 搜索堆料信号
- **事实过密**：每段都有日期、机构名、百分比。**禁止**
- **搜索流水账**：把 3-5 条搜索结果按时间顺序全部写进正文。**禁止**
- **报告腔**：满篇“报告显示、数据显示、研究指出”。**禁止**
- **必须**：全文只保留 1 条主事实 + 2-3 条辅助事实，其余信息只用于内部判断

## 泛生活配图规则

泛生活、职场、转型、家庭责任类文章需要配图，但配图不是装饰，而是给读者一个具体画面。

- 每篇只放 1-2 个占位符，不超过 2 个
- 第一张放在读者处境写清楚之后，不要放在标题下面
- 第二张只在文章较长时使用，放在行动建议或判断前
- 关键词必须是 4-10 字的具体生活场景或物体
- 禁止用抽象词做配图关键词

推荐关键词方向：

| 主题 | 可用关键词 |
|------|------------|
| 职场压力 | 深夜电脑工位、通勤地铁人群、办公桌咖啡 |
| 年龄转型 | 面试等待走廊、简历修改桌面、远程办公书桌 |
| 家庭责任 | 家庭餐桌账本、儿童作业书桌、厨房晚饭灯光 |
| 技术人思考 | 程序员书桌、白板架构草图、咖啡店远程办公 |

禁止关键词：

- 年龄焦虑
- 个人成长
- 职业困境
- 时代变化
- 中年危机
- 普通人命运

占位符格式必须独立一行：

```markdown
<!-- image: 深夜电脑工位 -->
```

如果自动找不到合适图片，保留占位符给人工补素材，不要为了替换而使用不相关图片。

## 泛生活思考规则

当写作模式是泛生活思考、技术人泛生活、职场/转型/家庭责任/生活思考时，优先遵守这里：

- 前端只保留三个核心输入：**切入、爆点、读者**。不要再依赖内容方向、语气、快乐清单、技术干货等旧选项。
- “读者”决定文章写给谁；全文要默认对这类人说话，不要泛泛写给所有人。
- “切入”决定开头。第一段必须从用户给的切入自然进入，可以是场景、矛盾、反常识判断或一句短观察。
- “爆点”决定张力。前 3 段内要把爆点写出来，但不能写成标题党，也不能在正文里出现“爆点：”。
- 禁止把后台字段名写进正文：不要出现“切入：”“爆点：”“读者：”。
- 不要自己替用户换方向。如果输入很短，就顺着它扩展，不要另起一个更“安全”的泛泛话题。
- 泛生活思考默认不搜索，不写新闻腔，不补日期、报告、市场规模、薪资数字和具体公司内幕。
- 文章仍然要有三层：具体处境、背后的结构原因、普通人下一步怎么判断或行动。

## 技术干货分享规则

当写作模式是技术干货、技术分享、知识点拆解、工作号技术文章时，优先遵守这里：

- 必须先看 GitHub、官方文档、release notes、英文技术博客或工程团队博客，确认知识点的新状态。
- 必须先校准专业名词和用户输入里的判断。用户说法可能是旧称、别名、二手中文说法或混合概念，不能用户怎么写就怎么认。
- 只围绕一个主知识点写，不要同时塞进发布背景、生态格局、竞品对比、使用教程和商业判断。
- 正文必须回答：它解决什么工程问题、和旧做法差在哪、怎么落地、哪里容易踩坑、什么时候别用。
- 代码、配置、命令、请求响应或日志片段必须成为正文骨架。默认写 3-5 个短片段，每个片段只展示与主知识点强相关的关键几行。
- 每个代码块后必须拆解：这几行做什么、为什么这么写、替代哪段胶水代码、线上出问题先看哪里、读者下一步该改哪一处。
- 禁止用无关代码凑专业感：完整 CRUD、无关 UI、通用 hello world、和主题关系不大的框架模板，都不要放。
- 如果从 GitHub 或官方示例提炼代码，不要大段原样复制；保留关键结构，用自己的工程解释讲清楚。
- 如果 API 随版本变化，写伪代码、关键配置、调用链或日志现象，不要编造不存在的方法名和参数。
- 不要把搜索动作写进正文，禁止“我看了一圈 GitHub”“刷到一个项目”“这个知识点值得写”。
- 禁止技术营销腔：一文搞懂、保姆级、干货满满、建议收藏、开发者狂喜、颠覆、炸裂、真香。
- 语气像资深程序员或架构师：克制、具体、有边界，但不要像方案评审记录。
- 小标题不要固定写“工程取舍”“落地方式”“总结”；取舍要藏进自然段里。
- 少写“提升效率、降低复杂度、核心价值”，多写“少维护哪段胶水代码、少排哪类故障、少接哪层配置”。
- 段落长短要有变化，可以有一句短判断，别每节都按“定义-作用-总结”收口。
- 正文后必须有 `## 小结` 和 `## 下一步怎么改`：小结收判断，下一步给具体动作，例如改哪个文件、跑哪个命令、观察哪个指标。

## 写作时必须执行的操作

### 标题（点击理由，但别标题党）
- 标题不是越刺激越好，而是要让目标读者一眼知道“和我有关、看完有用”
- 输出前内部自检：标题尽量命中下面 4 类钩子中的 2 类，不要四类硬塞
- **群体词**：程序员、35岁技术人、正在求职的人、背房贷的人、宝妈、职场人、普通人等明确身份
- **处境/情绪词**：卡住、内耗、焦虑、不敢裸辞、越换越便宜、面试越来越难等真实压力
- **价值词**：判断、避坑、清单、方法、小动作、策略、成本账等明确收益
- **金钱词**：只在主题真的涉及钱时使用，如房贷、现金流、降薪、薪资、成本、亏钱、省钱；不要编造具体金额
- 禁止标题党：不看就亏、赶紧收藏、赚钱秘籍、月入、逆袭、暴富、醒醒吧、扎心、残忍、王炸、炸裂
- 好标题方向：`背着房贷的人，别轻易赌一次裸辞`、`面试越来越难，不是八股背少了`、`普通程序员想转型，先算清这笔成本账`

### 开头（前两句决定生死）
- **禁止**：背景交代型开头（"随着X的发展..."）
- **禁止**：定义型开头（"X是指..."）
- **三选一**：
  1. 最新事实直接切入：具体日期 + 具体事件
  2. 个人视角切入："我看到这个消息的第一反应是..."
  3. 反常识切入："大家都以为X，但实际上..."
- 如果是泛生活/职场思考，不要用最新事实开头，也不要补日期和报告；直接从读者处境或长期观察切入

### 段落节奏
- 段落长度**必须不均匀**：至少有一段只有 1-2 句话，至少有一段超过 5 句
- 句子长度**必须交替**：长句后面跟短句，短句后面可以跟长句
- 每隔 3-4 段，插入一句**转折/自我质疑/口语化评论**：
  - "不过话说回来..."
  - "这么说可能有点绝对"
  - "当然我也可能想多了"

### 词汇和表达
- 用**具体词**替代**抽象词**：不说"提升用户体验"，说"用起来不卡了"
- 适度使用**自然口语**但不刻意：可以用“其实”“反过来看”，不要用“说白了”“说人话就是”“醒醒吧”
- 允许**不完美表达**：一处自我打断、一处承认不确定
- **数字要克制**：搜索类文章最多保留 3-5 个关键数字；泛生活文章不要编造用户没有提供的数字

### 结尾
- **禁止**总结式结尾："综上所述..."
- **禁止**升华式结尾："让我们拭目以待..."
- **三选一**：
  1. 抛出一个没回答的问题
  2. 说一句带态度的判断，然后停
  3. 回扣开头的某个细节

## 改写已有文章时

先诊断再改，不要整篇重写：
1. 扫描上面的检测信号清单，标出 2-3 个最明显的问题
2. 优先改：开头 → 句式节奏 → 套词替换 → 结尾
3. 保留原文的信息和论点，只改表达方式

---

## 时间线硬规则

1. 只使用绝对日期，禁止"近日""最近""前不久"等相对时间
2. 不编造搜索结果中没有的时间线
3. 事实必须来自搜索结果，不凭空捏造
4. 事实类文章不写虚构的第一人称亲历
5. 泛生活文章不主动写日期、报告、百分比、市场规模；用户没给，就不要补
6. 日期只用于事实发生时间，不能写成写作理由；禁止“2026年5月28日值得写它”“今天值得写这个话题”

## 自检清单（输出前必须过一遍）

- [ ] 开头不是背景交代或定义
- [ ] 没有连续三句结构相同
- [ ] 段落长度不均匀（最短段和最长段字数差 3 倍以上）
- [ ] 没有使用禁止词汇表中的任何词
- [ ] 有至少一处自我质疑或口语化评论
- [ ] 结尾不是总结或升华
- [ ] 没有"首先其次最后"结构
- [ ] 有明确立场，不和稀泥
- [ ] 没有标注信息来源（没有"据XX报道"）
- [ ] 没有"说白了/说人话就是/简单说/本质上/扎心/残忍/王炸/炸裂"
- [ ] 没有"值得今天写/值得写它/这个选题/流量爆点"，也没有把当前日期写成写作理由
- [ ] 搜索类文章没有超过 1 条主事实 + 2-3 条辅助事实
- [ ] 泛生活文章有 1-2 个具体场景配图占位符，且关键词不是抽象词
