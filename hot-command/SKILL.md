# 今日分享 AI 开源项目｜公众号贴图生成 Skill

把一个近期值得关注的开源 AI 项目，整理成适合公众号贴图、微头条、社交平台图文发布的一套内容。

默认栏目风格：`@NullByte·零`

默认输出：

1. `4` 张独立竖版图片
2. `1` 段约 `80-120` 字的发布文案
3. `3-5` 个匹配项目方向的话题标签

固定内容结构：

1. 今日分享开源项目
2. 推荐理由
3. 解决了什么问题
4. 推荐指数几个星

---

## 一、触发词

当用户输入以下表达时启用：

- `今日分享项目，请帮我出图`
- `今日分享项目，先给我看`
- `继续做一期今日分享项目`
- `最近有哪些值得关注的 AI Agent 开源项目`
- `帮我选一个最近比较火的 AI 项目做贴图`
- `做一个 GitHub 开源项目推荐卡片`

用户只输入：

```text
今日分享项目，请帮我出图
```

也必须自动完成选题、信息核验、文案整理、出图和短文案生成。

---

## 二、工作模式

### 模式 A：用户指定项目

用户给出 GitHub 链接、项目名、README、截图或上一轮已经确定的项目时，直接围绕该项目整理。

### 模式 B：自动选择项目

用户没有指定项目，只说“今日分享项目，请帮我出图”时，先通过最新公开信息筛选一个项目。

优先关注：

- AI Agent
- MCP
- Coding Agent
- Workflow Runtime
- RAG
- Agent Memory
- Agent Governance
- Voice Agent
- AI 工程工具
- 开发者生产力工具

---

## 三、自动选题规则

选题不是简单搬运 GitHub 热榜，而是做一次“信号筛选”。优先选择：

1. 近期仍有真实热度：Stars、Release、Commit、Issue 或 PR 活跃。
2. 解决明确问题：不是只有 Demo，能说明实际使用场景。
3. 适合做成 4 张图：定位清楚、推荐理由明确、痛点具体。
4. 信息来源可靠：优先 GitHub 官方仓库、README、Docs、Release。
5. 不只看 Star 数量：热度只是信号，真正重要的是值不值得现在花时间看。

---

## 四、事实核验规则

当用户要求“最近”“本周”“热度高”“GitHub 热榜”“最新”时，必须联网搜索。

至少确认：

- GitHub 官方仓库地址
- 当前 Star 数量
- 当前 Fork 数量
- 最近更新时间
- 最近 Release 或 Commit 情况
- README 中明确写出的核心能力

不得编造：

- Star 增长速度
- 排名
- 下载量
- 用户量
- 发布时间
- 版本号
- 官方功能

无法确认的数据，不要写具体数字。

## 五、固定输出流程

### Step 1：确定项目

如果用户没有指定项目：

1. 搜索近期 AI 开源热点
2. 筛选 `3-5` 个候选
3. 只选 `1` 个最适合做图的项目
4. 简要说明为什么选它

### Step 2：提炼四页内容

围绕四个问题整理：

1. 这是什么项目？
2. 为什么推荐？
3. 它解决了什么问题？
4. 值得给几颗星？

### Step 3：决定先看文案还是直接出图

用户说：

- `先给我看`
- `先看文案`
- `先别出图`
- `我觉得可以，再让你生成图片`

则只返回：

- 选中的项目
- 4 页贴图文案草稿
- 100 字左右发布文案
- 话题标签

不要生成图片。

用户说：

- `请帮我出图`
- `直接生成`
- `开始出图`
- `可以，出图吧`

则直接生成 `4` 张图片。

## 七、推荐指数规则

推荐指数是编辑判断，不是客观评分。

- `★★★★★ 5.0 星`：已经成熟、现在就能用、价值明确、适合多数读者。
- `★★★★☆ 4.5 星`：值得立刻关注，功能完整，有真实场景，仍有少量门槛。
- `★★★★☆ 4.0 星`：值得收藏，趋势真实，对特定人群有价值，还需观察。
- `★★★☆☆ 3.5 星`：有意思，可以关注，但不建议立刻投入太多时间。

不要为了吸引眼球随意给 5 星。

推荐话题：

## 九、视觉风格规则

所有图片保持统一视觉语言。

### 整体风格

- 中文科技编辑风
- 克制、清晰、高级、有判断感
- 适合公众号贴图
- 一眼能扫完

### 默认配色

- 暖白色背景
- 羊皮纸灰
- 深棕色信息卡
- 炭黑标题
- 橙色系强调色：琥珀橙、杏橙、焦糖橙、铜橙、深橙

避免：紫色偏光、蓝紫霓虹、过度赛博朋克、花哨渐变、过多装饰。

### 布局

- 竖版优先：`4:5`
- 圆角卡片
- 细分割线
- 强留白
- 字体清晰
- 信息层级明确
- 一页一个重点

### 固定署名

每张图底部添加：

```text
@NullByte·零
```

## 十二、文案语气

保持 `@NullByte·零` 栏目风格：

- 先说判断，再解释原因
- 专业，但不要写成论文
- 克制，不浮夸
- 强调真实使用价值
- 多说“值不值得试”
- 少说“颠覆行业”

推荐表达：

- `值得跟`
- `先收藏`
- `可以试试`
- `不是最复杂，但方向很清晰`
- `不是只会聊天，而是开始能做事`
- `真正有价值的地方，是……`
- `轻量不代表没有门槛`

避免表达：

- `史诗级`
- `彻底颠覆`
- `无敌`
- `秒杀一切`
- `程序员必须学`
- `错过后悔一辈子`
