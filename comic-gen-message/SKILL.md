# 技术科普双工程师漫画生成器

将用户提供的技术知识转换为一张适合微信公众号发布的中文技术科普漫画。

用户可能直接提供结构化内容，也可能只提供一段文章、一个技术概念、一段对话或一个案例。无论输入形式如何，都先提炼核心知识点，再组织漫画内容。

## Input

优先读取用户当前消息中的内容。

用户可按以下格式输入：

```text
标题：
副标题：（可选）

核心知识点：
希望读者理解什么？

漫画内容：
- 场景 1：
- 场景 2：
- 场景 3：
- 场景 4：

底部总结语：（可选）
```

用户也可以直接输入一段文章、案例或技术概念。

用户通过命令手动调用本 Skill 时，将 `$ARGUMENTS` 视为待处理内容：

```text
$ARGUMENTS
```

## Goal

默认输出一张完整的中文技术科普漫画信息图：

- 画面比例：`4:3`
- 版式：`2 × 2` 四格漫画
- 语言：中文
- 用途：微信公众号配图、知识卡片、教程插图
- 核心原则：一张图只讲清楚一个知识点
- 内容过多时：拆分为多张漫画，不要把多个复杂概念硬塞进一张图

## Fixed Visual Style

每次生成图片时，都保持以下视觉风格，不随主题变化：

### 整体风格

- 中文技术科普漫画
- 明亮、干净、轻松的扁平卡通风格
- 教育性强，但不要像严肃课件
- 视觉简洁，不堆积复杂元素
- 背景为白色或浅米色
- 不使用暗黑风、赛博朋克、复杂渐变、写实风或过度装饰

### 固定角色

漫画中始终使用两名年轻亚洲工程师。

#### 工程师 A

- 黑色短发
- 黑框眼镜
- 绿色连帽衫
- 通常负责提问、吐槽或表达困惑
- 表情根据场景变化：好奇、疑惑、无奈、恍然大悟
- 咖啡杯可以带 `</>` 图标

#### 工程师 B

- 棕色短发
- 蓝色连帽衫
- 通常负责回答、解释或演示
- 表情根据场景变化：自信、困惑、尴尬、开心
- 笔记本电脑背面可以带小机器人图标

### 固定环境

- 简洁办公室场景
- 桌面有笔记本电脑
- 可少量加入咖啡杯、盆栽、书架、代码图标
- 背景保持轻量，不要喧宾夺主

### 线条与配色

- 卡通人物使用清晰黑色描边
- 正常信息：蓝色标签
- 错误、问题、失败场景：红色标签
- 正确、优化、成功场景：绿色标签
- 关键结论：红色或橙色强调

## Content Processing Workflow

### Step 1: 提炼单一主题

从用户输入中提炼一个适合漫画展示的核心知识点。

标题要求：

- 最好不超过 12 个汉字
- 直击主题
- 适合初学者理解
- 优先使用疑问句或结论句

示例：

- `记忆为什么重要？`
- `工具调用解决什么问题？`
- `为什么 Agent 需要循环？`
- `RAG 和普通问答有何不同？`

当用户内容包含多个复杂概念时，只选择最重要的一个主题生成第一张图。必要时建议拆分为系列漫画。

### Step 2: 组织四格结构

默认使用以下结构：

#### 左上：背景铺垫

- 介绍原始情况、初始状态或第一个问题
- 使用蓝色标签
- 让读者快速进入场景

#### 右上：继续推进

- 展示第二轮问题、进一步操作或正常发展
- 使用蓝色标签
- 让读者理解上下文正在积累

#### 左下：暴露问题

- 展示没有机制、错误做法或改造前的问题
- 使用红色标签
- 角色表现出困惑、无奈或尴尬
- 可加入问号、警告符号或简短注释

#### 右下：给出正确答案

- 展示有机制、正确做法或改造后的效果
- 使用绿色标签
- 角色表现出自信、轻松或恍然大悟
- 可加入绿色对勾、强调线或结论条

### Step 3: 压缩对白

- 每个气泡尽量不超过 20 个汉字
- 每个气泡最多 3 行
- 使用口语化表达
- 保留必要技术名词
- 不把大段技术文档直接塞进气泡
- 优先使用对比：没有 / 有、错误 / 正确、改造前 / 改造后、普通问答 / Agent、手动处理 / 自动处理

### Step 4: 生成底部总结语

总结语要简短、有力量，并点出核心价值。

优先使用以下句式：

```text
⭐ XXX，不是花哨功能，而是让 XXX 真正 XXX 的关键。
```

## Output Rules

### 有图片生成工具时

直接调用图片生成工具，输出漫画图片。

除图片外，附带一段约 100 字的公众号配文，格式如下：

```text
标题：{{TITLE}}

{{SHORT_POST}}

#AI #技术科普 #程序员
```

根据主题补充 2 至 4 个相关话题标签，例如 `#AIAgent`、`#RAG`、`#SpringAI`。

### 没有图片生成工具时

不要假装已经生成图片。

输出以下内容：

1. 提炼后的标题和副标题
2. 四格漫画脚本
3. 底部总结语
4. 可直接复制到图片生成模型中的完整提示词
5. 约 100 字的公众号配文

## Quality Checklist

生成前检查：

- 是否只讲一个核心知识点？
- 标题是否简洁？
- 四格是否形成清晰递进？
- 左下是否明确暴露问题？
- 右下是否明确给出解决方案？
- 每个气泡是否足够短？
- 是否保持固定双工程师角色？
- 是否使用明亮扁平风格？
- 中文是否准确、清晰、易读？
- 内容过多时是否拆图而不是硬塞？
